關於我

來自台中烏日，家族經營塑膠射出工廠，從小在製造業現場長大， 習慣把「能跑起來、穩定不出包」當作做事的最低標準。

做專案喜歡走完整條路：從硬體（Raspberry Pi、感測器）到後端（Flask / Next.js）、 排程（GitHub Actions / Vercel Cron）、AI 整合（Gemini / LLM API）、再到 UI。 相比鑽研單一框架，我更在意「整個系統能否每天自己跑、出錯能不能自動通知」。

最近也把同樣的思路用在設計工作上：與展覽方合作時，我把「手工排 13 張卡片」變成 改一份資料就能重出 PNG、向量 PDF、SVG、HTML 四種格式的生成系統， 並用程式繪製與合成完成主視覺。對我來說，設計交付一樣要「可重跑、可修改、不用求人重做」。

求職方向上，除了 IoT、嵌入式、AI 自動化等工程職， 我也積極尋找一般行政、營運支援與專案協調類的職位。 在製造業現場長大，加上實際幫家裡工廠與合作對象導入過庫存、訂單、報表的自動化， 讓我在文書處理、流程整理、Excel／Google Sheets 與跨部門溝通上同樣能快速上手。

不論是工程還是行政，我看重的是同一件事：把事情做得穩定、流程交代清楚、可以被信任。 目前也持續自學日文（目標 N3）。

展覽視覺卡片程式化生成系統

Design Automation
🏛️ 實際用於展覽：情緒診療室 — 閱讀處方總覽展
Node.js / Playwright / HTML Canvas / SVG / 向量 PDF

展覽方提供文案與設計方向，我負責把它變成「改資料就能重出全部成品」的生成系統： 13 張處方箋卡片由一份資料源驅動，一鍵輸出 PNG（社群／列印）、可編輯的向量 PDF、 可拖進 Figma 續修的 SVG，以及可直接改樣式的 HTML 原始版型；另附 A4 雙面落版（一張紙兩張 A5）。

技術亮點：以 Playwright 驅動無頭瀏覽器渲染 Canvas／HTML 版型再截圖輸出，四種格式共用同一份排版邏輯； 主視覺全程用程式繪製與合成——照片轉灰階拉曲線 → 45° 圓點網屏半調（halftone）→ 拍立得邊框與陰影 → 復古桌面場景疊合 → 暖褐×墨青統一調色，並做出 9 種構圖變體讓展覽方挑選； 內文長度不一時自動均分段落高度、預先算好斷行，避免文字溢出或截斷。

交付上刻意讓非工程師也能自己重跑：一個 .bat 雙擊執行（首次自動安裝依賴）、 附中文操作說明與 Figma 匯入指引；素材全部使用 Pexels 免費可商用授權並在程式內註記來源 ID。

※ 文案與書單內容為展覽方所有，此處僅展示我負責的視覺生成成果；生成腳本含展覽文案，故不公開原始碼。
